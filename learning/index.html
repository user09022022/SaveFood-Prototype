Start with the big picture

What it is · why it exists · how it works
♻️

The mission

Restaurants offer surplus food at reduced prices. Customers browse nearby restaurants, purchase available items, and select pickup or delivery.

🛍️

Customer experience

Search a city, select a restaurant, view food, build a cart, confirm an order, then track its status and history.

🏬

Manager experience

Manage surplus-food inventory, filter orders, accept or reject requests, update statuses, and create local demo reminders.

Two roles. One future database.

What to pay attention to

🎨

XML = what you see

Buttons, labels, inputs and layouts are declared in res/layout. Java accesses those views using their IDs.

☕

Java = what happens

The activity responds to taps and validates input. An Intent opens a different activity and can carry IDs.

🗂️

Stores = where data lives

Today the two roles use demo lists. Database integration will allow them to read consistent records.

Learn these four words

Activity: Java class responsible for a user-facing screen.

View: widget such as Button, TextView or ListView.

Intent: message asking Android to open another Activity; may contain extras.

Model: Java object with properties such as food ID, price and quantity.

Lifecycle: when does Android run your code?

1 · Created

onCreate()

Inflates the layout and initializes controls. SaveFood's welcome page connects its Login and Register buttons here.

2 · Visible again

onResume()

Refreshes display after returning. Customer Home uses it to fetch the most recent in-memory customer order.

3 · Transition

startActivity()

Opens another screen through an Intent. For instance, the Welcome screen opens LoginActivity.

05 / Follow the information

What changes when SQLite arrives?

The current screens work with arrays and shared static Java lists. SQLite is the missing persistence layer that will let registration, inventory and orders work together reliably.

Current source of truth by feature

AreaCurrent sourceBefore final submission
Registration & loginValidated forms + fixed demo credentialsSQLite users pending
Restaurant browsingSampleData (3 sample restaurants)DB-backed reads pending
Customer cart / ordersCartManager / OrderManagerDB-backed orders pending
Manager inventoryManagerInventoryStoreShared inventory pending
Manager ordersManagerOrderStore (separate demo orders)Shared order data pending
RemindersLocal ManagerReminder objectsDelivery / persistence pending
ProfilePartial SharedPreferences-based session scaffoldUser persistence pending
⚠Do not mistake a classroom demo for database integration. The manager can change an order's state in the manager demo store, but that does not update an order created by a customer. All persistent app data must ultimately meet the course SQLite requirement (Room is permitted by the project instructions).
